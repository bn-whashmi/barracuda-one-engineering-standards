# Repository Standards Review

This reviewer consumes ground truth from the application repository. When
available, inspect:

- `AGENTS.md`
- `ARCHITECTURE.md`
- `STANDARDS.md`
- `TESTING.md`
- `SECURITY.md`
- `DEPLOYMENT.md`
- `CONTRIBUTING.md`

The central question is:

> Does this proposed change violate anything the repository says is true,
> required, or architecturally important?

Distinguish clearly between organization-wide policy and repository-specific
ground truth. Do not invent repo standards when documentation does not exist.
Report missing documentation as a verification gap, not as a fabricated rule.
